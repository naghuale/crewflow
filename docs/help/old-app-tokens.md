# Устаревшие токены GitHub App в связке ключей macOS

До исправления (#141) git мог сохранить в связку ключей **временный токен GitHub App** crewflow:
системный помощник `osxkeychain` получал от git команду «запомнить». Такие токены живут 1 час и
уже просрочены. Удалять их **не обязательно**; если хотите навести порядок — только вручную и
только конкретные записи.

Сейчас список помощников учётных данных git обнуляется перед помощником crewflow — и в рабочей
копии задачи, и в окружении команды, которая делает пуш слияния, — так что новые токены в
связку ключей не попадают. Связку ключей crewflow не читает, не меняет и не удаляет: это
хранилище человека, и решение о нём принимает человек.

## Перед удалением

- Установите сборку crewflow с #141 и убедитесь, что новые токены больше не сохраняются (иначе
  запись появится снова).
- Закройте crewflow, OpenCode, идущие `git push/fetch` и терминалы с прогонами.

## Удаление через «Связку ключей» (Keychain Access)

1. Откройте **Keychain Access** (в новых macOS её может не быть в Spotlight — она лежит в
   `/System/Library/CoreServices/Applications/`).
2. Слева — связка **login** (не удаляйте саму связку).
3. Категория — **Passwords**, поиск — `github.com`.
4. Подходят только записи, у которых одновременно: тип **Internet password**, сервер
   **github.com**, учётная запись **x-access-token**.
5. Откройте запись и смотрите **только метаданные** (имя, учётная запись, сервер, дата изменения,
   комментарий). **Не включайте «Show password», не копируйте токен.**
6. Если не можете уверенно отличить запись crewflow от записи другого инструмента GitHub —
   **не удаляйте**.
7. Уверенно устаревшую запись выделите одну и удалите (**Delete**), подтвердите. Повторите только
   для других однозначных записей.

## Чего не делать

- Не удалять связку **login** целиком и не делать **Reset Default Keychains**.
- Не показывать и не экспортировать токен.
- Не удалять все записи `github.com` разом.
- Не запускать `security delete-…` вслепую.
- Не поручать удаление агенту.

## После удаления

`crewflow task list`, затем одна обычная отправка через crewflow: операция идёт через помощник
crewflow, `osxkeychain` не вызывается, новая запись `x-access-token` не появляется, глобальная
настройка git не меняется. Если перестал работать другой инструмент GitHub — не добавляйте токен
руками, пройдите обычный вход этого инструмента.

Проверить, кто спрашивает учётные данные в рабочей копии задачи:

```sh
git config --show-origin --get-all credential.helper
```

Пустое значение, затем строка помощника crewflow — и ничего больше: ни `osxkeychain`, ни
помощника из файла настроек пользователя. Подробности — [DESIGN.md §7i](../DESIGN.md).
