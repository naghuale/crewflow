### Добавлено

- **Журнал изменений собирается из фрагментов: `changelog.d/<задача>.md`.** Почти каждая задача
  писала строку в общий `CHANGELOG.md`, и две задачи, не пересекающиеся ни в коде, ни в
  документах, конфликтовали при слиянии второй: 01.10 задача #100 после #107, telecli #68
  перенесён дважды после #72 (F-086). Теперь задача пишет **свой** файл `changelog.d/<N>.md` —
  разделы журнала и строки для человека, как сейчас, — а журнал собирается из всех фрагментов.
  Чужой фрагмент задача не трогает: он вне её границ, и ворота скажут `out-of-scope`.
  (задача [#124](https://github.com/naghuale/crewflow/issues/124))

- **`crewflow changelog build`** собирает раздел «## [Не выпущено]» из фрагментов: по разделам
  журнала, а внутри раздела — по порядку слияния, взятому из истории git (коммит, который
  добавил фрагмент), а не по номерам задач. Сборка идемпотентна и детерминирована: повторная
  сборка без изменений не трогает файл, момент сборки, порядок файлов на диске и локаль в
  результате не стоят ничего. Фрагменты, вошедшие в историю одним коммитом, читаются по номеру
  задачи, больший сверху, — иначе порядок зависел бы от того, как git обошёл коммиты.
  (задача [#124](https://github.com/naghuale/crewflow/issues/124))

- **`crewflow changelog check`** — ворота журнала, и проверка входит в ворота проекта: формат
  каждого фрагмента, что номер в имени — существующая задача, что нет дублей (одна строка в
  двух фрагментах, одна задача с двумя файлами) и что собранный `CHANGELOG.md` совпадает со
  сборкой. Каждая причина названа своим словом и файлом со строкой; `-json` отдаёт те же
  причины полями для оркестратора.
  (задача [#124](https://github.com/naghuale/crewflow/issues/124))

- **`crewflow changelog release <версия>`** — шаг выпуска: невыпущенный раздел получает номер
  и дату, над ним остаётся пустой, фрагменты убираются. Один коммит выпуска, и ни одна строка
  выпуска не попадает в следующую версию второй раз. Пустой невыпущенный раздел собирается
  обратно в себя же, поэтому первый build после выпуска не пишет раздел в пустоту.
  (задача [#124](https://github.com/naghuale/crewflow/issues/124))

### Изменено

- **Выпуск версии.** `scripts/release.sh` больше не требует, чтобы человек переписал раздел
  невыпущенного вручную: он собирает журнал, отдаёт разделу версии номер и дату и убирает
  фрагменты, а тег, как и раньше, остаётся решением человека — команда печатает его, но не
  ставит. Ссылка в конце журнала остаётся как была: она называет коммиты ветки, а
  невыпущенный раздел и есть они.
  (задача [#124](https://github.com/naghuale/crewflow/issues/124))

- **Правило 3 PROJECT_RULES.md, шаблон задачи, чек-лист, README и DESIGN** говорят о фрагментах:
  границы задачи — `changelog.d/<N>.md`, а не `CHANGELOG.md`, и журнал не правится руками в
  обычной задаче — только сборкой.
  (задача [#124](https://github.com/naghuale/crewflow/issues/124))
